# Scrum Master: Enables the Team

## Definition

**Scrum Master** is a coach and facilitator.

❌ NOT a project manager
❌ NOT a boss
❌ NOT a micromanager

✅ **IS** a coach who removes blockers and enables the team to do Scrum well.

---

## Main Responsibilities

### 1. Run Ceremonies on Time

**What:** Make sure Sprint Planning, Standups, Review, and Retro actually happen.

**Sprint Planning:**
```
Marcus (SM): "We're starting. 2 hours. Let's go."
Sarah (PO): "Here are the top stories."
Marcus: "Team, questions?"
[Discussion]
Marcus: "Everyone agree on these 3 stories?"
Team: "Yes."
Marcus: "Sprint starts tomorrow. See you at standup."
```

**Daily Standup (15 min):**
```
Marcus: "15 minutes. Each person: yesterday, today, blockers?"
Alice: "Done registration form. Today API integration. Not blocked."
Bob: "Done registration API. Today testing. Blocked on database schema."
Marcus: "Let's talk after standup about that."
[Two more people]
Marcus: "Great. See you tomorrow."
```

---

### 2. Remove Blockers Immediately

**What:** If the team is stuck, fix it (or escalate to someone who can).

```
Carol (in standup): "I can't test without production database access."
Marcus: "You'll have it by 2 PM. Unblocked?"
Carol: "Yes."

Bob: "I need API documentation."
Marcus: "Alice, can you send that today?"
Alice: "By lunch."
Marcus: "Good. Bob, unblocked after lunch."

Dave: "Server is down. Can't deploy."
Marcus: "I'll call ops. You'll hear from me in 30 minutes."
(Later): "Server coming up. 30 more minutes."
Dave: "Good."
```

Marcus doesn't do the work. He **enables** the team to do it.

---

### 3. Protect the Team from Distractions

**What:** Keep interruptions out. Let people focus.

```
Executive: "I need a daily status report."
Marcus: "We have Sprint Review every Friday with working software.
Let's show you that instead of daily emails.
Better?"

Customer: "I need this feature right now!"
Marcus: "I hear the urgency. Let's talk to Sarah (PO) about priority.
Maybe next sprint?"

Manager (to Alice): "Can you help this other team?"
Marcus: "Alice is committed to JobConnect this sprint.
Let's discuss after Friday's review."
```

---

### 4. Facilitate Retrospectives

**What:** Run the meeting where the team talks about how to improve.

**Good retro:**
```
Marcus: "What went well?"
Alice: "We finished everything. Bob's code was clean."

Marcus: "What didn't go well?"
Carol: "We found bugs Friday. Should test earlier."

Marcus: "What will we do differently?"
Team: "Test as we code. Do peer review before 'done'."

Marcus: "Good. Let's try that next sprint."
(Everyone leaves feeling heard)
```

**Bad retro:**
```
Manager: "Why didn't you finish?"
Bob: "Alice was too slow."
Alice: "Carol delayed testing."
Carol: "Dave didn't give us the server."
(Everyone leaves feeling blamed)

Result: Nobody improves. Same mistakes next sprint.
```

---

### 5. Coach the Team on Scrum

**What:** Help people understand and follow Scrum practices.

```
Bob (in standup): "Yesterday I coded 8 hours. Today I'll code 8 hours."
Marcus (after standup): "Bob, standup isn't a work log.
Just: yesterday, today, blocked?
That's all we need."
Bob: "Got it."

At retro:
Carol: "Bob's code is always messy."
Marcus: "Let's not blame individuals. Focus on process.
How can WE improve?
Maybe pair programming? Code review?"
Team: "Yes, more code review."
```

---

## ❌ When SM Role Breaks

### SM acts like a boss
```
Marcus: "I need this done by 5 PM. Move faster."

Result: Team feels controlled. Loses motivation.
Fix: Ask "What do you need?" not "Why isn't it done?"
```

### SM disappears
```
Marcus: "Planning is tomorrow. See you then."
(Doesn't run daily standups)
(Doesn't remove blockers)

Result: Team has no support.
Fix: SM is present. Daily. Available.
```

### SM is also PO
```
One person decides what to build AND how to work.

Result: Too much power in one person.
Fix: Separate roles. Different skills needed.
```
